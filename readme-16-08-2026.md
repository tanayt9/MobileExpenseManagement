## 2. Project Configuration

### `app.json` — Key Fields to Verify
Open `app.json` and confirm these values are correct before building:

```json
{
  "expo": {
    "name": "Expense Manager",
    "slug": "MobileExpenseManagement",
    "version": "1.0.0",
    "android": {
      "package": "com.tanayp.mobileexpensemanagement",
      "versionCode": 1,
      "adaptiveIcon": {
        "foregroundImage": "./assets/images/adaptive-icon.png",
        "backgroundColor": "#6366f1"
      }
    }
  }
}
```

> **Important:** Every time you upload a new build to Play Store, you must increment `versionCode` (e.g., 1 → 2 → 3). The `version` string (e.g., "1.0.1") is what users see. With `eas.json` set to `"autoIncrement": true`, EAS handles the `versionCode` automatically.

### `eas.json` — Production Build Profile
Your `eas.json` production profile is already configured correctly:
```json
{
  "build": {
    "production": {
      "autoIncrement": true
    }
  }
}
```

## 3. EAS Build Setup

### Step 1 — Login to Expo
```bash
eas login
```

### Step 2 — Link Project to EAS
```bash
eas init
```
> If you already have a `projectId` in `app.json → extra.eas.projectId`, skip this step.

### Step 3 — Configure Android Credentials (Keystore)
EAS will manage your keystore automatically (recommended):
```bash
eas credentials
```
Choose `Android → production → Keystore → Generate new keystore`.

> ⚠️ **Critical:** EAS stores your keystore securely in the cloud. Download and back up your keystore file:
> ```bash
> eas credentials -p android
> # Then select: Download Keystore
> ```
> **Never lose this keystore.** You cannot update your app on the Play Store without it.

## 4. Generate a Release AAB

Google Play requires an **Android App Bundle (.aab)** — not an APK — for new apps.

### Build Command
```bash
eas build --platform android --profile production
```

This will:
1. Upload your project source to EAS servers
2. Install dependencies and run the build
3. Sign the `.aab` with your production keystore
4. Provide a download URL when complete

### Monitor Build
- Watch progress in the terminal, or
- Visit [expo.dev/accounts/[username]/projects](https://expo.dev) → Your Project → Builds

### Download the AAB
Once complete, download the `.aab` file from the Expo dashboard link provided. Save it as:
```
MobileExpenseManagement-v1.0.0.aab
```

## 5. Google Play Console Setup

### Step 1 — Create a New App
1. Go to [Google Play Console](https://play.google.com/console)
2. Click **"Create app"**
3. Fill in:
   - **App name:** `Expense Manager`
   - **Default language:** English (United States)
   - **App or game:** App
   - **Free or paid:** Free
4. Accept the declarations and click **"Create app"**

### Step 2 — Complete App Setup Tasks
The Play Console will show a setup checklist. Complete all items:

#### a) App Access
- Select **"All functionality is available without special access"** (or provide login credentials if the app requires sign-in)

#### b) Ads
- Select **"No, my app does not contain ads"**

#### c) Content Rating
- Click **"Start questionnaire"**
- Category: **Utility**
- Answer all questions honestly (no violence, no user-generated content, etc.)
- Submit to receive your rating

#### d) Target Audience
- Select target age: **18 and over**
- Confirm the app is not primarily child-directed

#### e) News App
- Select **"No"**

#### f) COVID-19 (if applicable)
- Select **"No"** — this is a finance utility app

#### g) Data Safety
Complete the Data Safety form carefully:

| Data Type | Collected? | Shared? | Required/Optional |
|---|---|---|---|
| Financial info (transactions) | ✅ Yes | ❌ No | Required |
| Device or other IDs | ❌ No | ❌ No | — |
| App activity | ❌ No | ❌ No | — |

- All data is stored **locally on device** (SQLite) — select "Not shared with third parties"
- Select "Data is encrypted in transit" → **Not applicable** (offline app)
- Select "Users can request data deletion" → Describe: "Users can delete all data from the app's Settings screen"

## 7. Upload & Submit for Review

### Step 1 — Create a Release
1. In Play Console → **Production** → **Create new release**
2. Click **"Upload"** and select your `.aab` file
3. Add **Release notes** (What's New):
   ```
   🎉 First release of Expense Manager!
   • Track income and expenses with ease
   • Secure biometric login (fingerprint/PIN)
   • Beautiful charts and category breakdown
   • 100% offline — your data stays on your device
   ```
4. Click **"Next"**

### Step 2 — Review the Release
- Review any warnings or errors flagged by Play Console
- Confirm all pre-launch report items are addressed

### Step 3 — Submit for Review
- Click **"Save"** then **"Publish to Production"** → **"Send [N] countries for review"**
- Review typically takes **1–3 business days** for first submission

### Optional: EAS Submit (Automated Upload)
You can automate the upload using EAS Submit:
```bash
eas submit --platform android --latest
```
> Requires setting up a Google Play Service Account API key. See: [EAS Submit Docs](https://docs.expo.dev/submit/android/)

## 9. Troubleshooting

### ❌ "Duplicate package name" error
Another app with `com.antigravity.mobileexpensemanagement` already exists on your account. Change the package in `app.json`:
```json
"package": "com.antigravity.expensemanager"
```

### ❌ Build fails: "SDK version mismatch"
```bash
expo doctor
npm install expo@latest
```

### ❌ Biometric login not working on release build
Ensure `expo-local-authentication` is in the `plugins` array of `app.json` and rebuild:
```bash
eas build --platform android --profile production --clear-cache
```

### ❌ "You uploaded an APK or Android App Bundle that was signed with a different certificate"
You must use the **same keystore** for all updates. Retrieve your stored keystore:
```bash
eas credentials -p android
```

### ❌ Play Store review rejected — Missing permission justification
Add the following to your Privacy Policy and Data Safety form:
- `USE_BIOMETRIC` / `USE_FINGERPRINT` — Used for secure app login only
